# 00. Starry Village 종합 구조 문서 (IP 제작 마스터)

기준일 2026-09-15. ChatGPT 세션(8/14~9/14)에서 논의한 결론을 실행 가능한 구조로 옮긴 것.
이 문서는 **전체 그림**이다. 세부는 01~04 문서로 내려간다.

---

## 1. 한 문장

> 별이 가까이 보이는 작은 도시에서, 가장 예쁜 소녀 **리아**가 매 스테이지 새 옷을 입고
> 그 옷 때문에 작은 사건을 만나며, 정체를 숨긴 **왕자님**과 조금씩 가까워지는
> 짧은 인터랙티브 연속극 — 을 **꾸미기 게임의 껍데기**로 만든다.

겉은 꾸미기 게임. 속은 짧은 로맨스 미스터리. 목적은 게임 매출이 아니라 **캐릭터 IP**.

---

## 2. 왜 이 구조인가

| 문제 | 우리 답 |
|---|---|
| 광고비 없이 어떻게 노출하나 | 게임이 광고판이 아니라 **콘텐츠 전체가 광고판**. 스테이지 1개 → 쇼츠 2~3 + 블로그 1 + 일러 |
| 옷입히기 HTML5는 이미 흔하다 | "예쁜 옷"이 아니라 **"이 옷 때문에 무슨 일이 생기나"** 로 차별. 다음 스테이지 버튼이 핵심 |
| AI 그림은 캐릭터가 매번 바뀐다 | 기준 이미지 참조 + 캐릭터 DNA 고정 + 코드는 id 매핑 → 나중에 통째 교체 |
| 스토리 분기는 개발비 폭발 | 큰 줄기·보상 고정, **표현만** 옷에 따라 바뀜 (스토리 슬롯) |
| 아동 타깃은 광고 단가 붕괴 | 광고수익을 1차 KPI 로 잡지 않는다. 노출당 제작비 + 다음스테이지 클릭률 |
| 최종물이 AI 면 저작권 약함 | 연재는 AI, 살아남은 캐릭터만 P5 에서 사람이 재설계 → Master Asset |

## 3. IP 구조

```
                  ★ STARRY VILLAGE ★
                         │
        ┌────────────────┼────────────────┐
      캐릭터            장소             이야기 엔진
  리아·왕자·엘라·     스타일스튜디오·      "오늘의 사건"
  허당남·별이         카페·정원·집·        + 왕자 정체 떡밥
                     우체국·광장
                         │
                    STORY SEED (주 2~3개)
                         │
      ┌─────────┬────────┼────────┬─────────┐
    게임 Stage  일러스트   쇼츠 2~3   블로그 1   히든 에피소드
      └─────────┴────────┴────────┴─────────┘
                         │
                    반복 노출 → "리아 알아!" → IP
```

### 3-1. 캐릭터 (4+1). 성격은 한 단어로 고정한다 — AI 가 계속 써야 하니까
| id | 이름 | 역할 | 한 단어 | 대표색 | 시그니처 |
|---|---|---|---|---|---|
| ria | 리아 | 주인공. 이 세계에서 가장 예쁜 소녀 | 예쁨·호기심 | 로즈핑크/크림/골드 | 왼쪽 별 헤어핀 |
| prince | (이름 미정, 가칭 "루안") | 허술해 보이는 남자. 실은 숨겨진 신분·능력 | 신비 | 네이비/실버 | 낡은 회중시계 |
| rival | 엘라 | 라이벌. 예쁘고 자신감. 왕자의 비밀을 일부 안다 | 자신감 | 와인레드/블랙 | 날카로운 눈, 긴 생머리 |
| goofy | (이름 미정, 가칭 "토토") | 허당남. 대단해 보이지만 진짜 허당. 코미디 | 허당 | 오렌지/옐로 | 둥근 얼굴, 넘어짐 |
| star | 별이 | 작은 별 친구. 세계관·내레이션·힌트 | 엉뚱 | 라이트옐로 | 반짝 꼬리 |

관계: 리아 ↔ 왕자(호감도), 리아 ↔ 엘라(경쟁), 허당남 → 리아(짝사랑, 코미디), 엘라 → 왕자(관심 + 과거를 앎).
상세 DNA·프롬프트는 `01_WORLD_BIBLE.md`.

### 3-2. 장소 = 게임 장르 매핑 (확장 라인업)
| 장소 | 파생 게임 | 순서 |
|---|---|---|
| 스타일 스튜디오 | 드레스업 (1호 Dress Story) | 1 |
| 문라이트 카페 | 주문/조합 (코코 역할은 리아 친구로 추가 가능) | 2 |
| 플라워 가든 | 꾸미기/색칠 | 3 |
| 스타 하우스 | 방 꾸미기 | 4 |
| 별빛 우체국 | 편지 분류/스토리 발생 | 5 |
| 스타리 페스티벌 | 계절 이벤트·패션쇼 | 시즌 |

엔진은 3개(꾸미기/조합/색칠)뿐. 게임 = 엔진 + 스킨 + 스토리. 마스터문서(시옷)의 "엔진 3개 + 스킨 교체" 원칙과 동일.

## 4. 게임 구조 (모든 호에 공통)

### 4-1. 스테이지 루프 (20~40초)
```
[상황 한 줄] → [옷 선택 3~5] → [리아 등장(결과 이미지)] → [사건 발생]
→ [왕자/엘라/허당 중 1~2명 등장, 대사 2~4줄] → [질문 한 줄로 끝] → [보상] → NEXT
```
마지막은 반드시 **답을 주지 않는 질문 한 줄**. ("왕자님은 왜 내 이름을 알고 있었지?")

### 4-2. 스토리 슬롯 — 큰 줄기 고정, 표현만 바뀜
```
Stage N
├─ situation        (고정)
├─ costume_choices  (3~5)  ──▶ 선택별 dialogue_variant 만 다름
├─ event            (고정)
├─ reward           (고정: 별조각 +N, 호감도 +1)
├─ hidden_episode   (조건: 재플레이 + 특정 의상 등 → 추억앨범에 수집)
└─ next             (고정: N+1)
```
플레이어 A 가 분홍, B 가 파랑을 골라도 **Stage N+1 해금·보상은 같다.**

### 4-3. 두 종류의 이야기
- Main: 01 → 02 → 03 … 한 방향.
- Hidden: 재플레이 시 조건 충족 → 짧은 장면 1개 + "왕자의 비밀 조각". 추억앨범에서 재열람.

### 4-4. 시즌 떡밥 (30스테이지 내외에서 회수)
왕자의 정체 / 엘라가 아는 과거 / 리아의 출생. 스테이지마다 조각 하나씩. 한꺼번에 공개 금지.
왕자 정체 공개 페이스 예시: S03 허술함 → S07 무심한 한마디로 사건 해결 → S12 엘라가 알아봄
→ S18 왕궁 사람들이 고개 숙임 → 시즌 말 설명.

### 4-5. 재화·보상 (1호 기준, 데이터로만 존재)
별조각(stardust): 스테이지 클리어 보상, 의상 해금에 사용. 호감도(affection): 왕자 루트 표시용, 숫자만.
IAP·서버 없음. 광고는 `showRewardedAd()` 추상 함수만(플랫폼 SDK 는 나중에 교체).

## 5. 아트 체계 (3단, 같은 DNA)

| Level | 용도 | 등신 | 규칙 |
|---|---|---|---|
| Hero | 스토리 일러·쇼츠·썸네일 | 6~7 | 예쁨 최우선, 파스텔, 부드러운 셀셰이딩, 깨끗한 선 |
| Game | 드레스업·대화·스테이지 | ~3 | 둥근 형태, 두꺼운 외곽선, 적은 음영, 3~4색, 큰 표정 |
| Sticker | UI·이모티콘·SNS | 1~2/얼굴 | 표정 6종(기쁨·놀람·당황·화남·슬픔·설렘), 투명 배경 |

일관성 유지 순위: **캐릭터 마스터 이미지 참조 > DNA 프롬프트 고정 > seed**. LoRA 는 P5 이후.
화풍 가칭 "Soft Story Kawaii". 전형적 AI 반짝이·렌즈플레어·과한 배경 금지. "아이들이 따라 그리고 싶은 캐릭터"가 기준.
드레스업 게임은 AI 가 아니라 **파츠 레이어**(body/hair/face/top/bottom/dress/shoes/bag/acc)로 캐릭터가 절대 안 바뀌게.

이미지 제작 단계: P2 에서 리아 1명만 7종 세트(Hero 전신 / Game 기본 / 의상 5벌 / 표정 6 / 왕자와 장면 / 대화창용 / 스티커). 성공하면 왕자 → 엘라 → 허당남 → 별이.

## 6. 콘텐츠 파이프라인 (세부 03 문서)

```
Story Seed #N (사건 한 줄)
  → stage_N.json (게임)
  → 일러스트 1~2 (Hero)
  → 쇼츠 대본 2~3 (15~20초, 마지막에 로고+캐릭터)
  → 블로그 1 (세계관 일기 or 개발기)
  → 히든 에피소드 후보 1
```
주 2~3 시드. 하나의 시드가 최소 5회 재사용되지 않으면 AI 경제성이 안 나온다.

채널: 쇼츠(유튜브/틱톡/인스타 릴스) → 발견 / 블로그(네이버 siot74·티스토리) → 기록·개발기 / 게임 → 놀이.
캐릭터 수다방(가상 채팅, 캐릭터끼리)은 콘텐츠 포맷으로만. 실제 사용자 채팅은 하지 않는다(아동 안전·운영 부담).

## 7. 배포·정책

- 1차: 자체 웹(단일 HTML) + 블로그 링크. 2차: 모비게임 경유 삼성 Instant Plays, 토스 앱인토스(게임위 등급분류 선결), 틱톡 인스턴트, 카카오.
- 포지셔닝: "전연령 힐링/스토리"로 **실제로** 만든다. 유아 전용 등록 금지, 아동 지향 우회 표시 금지.
- 콘텐츠 안전: 로맨스는 "설렘" 선까지. 신체 접촉·성적 묘사 없음. 악역은 질투·경쟁 수준.
- 저작권: AI 원본·프롬프트·사람 수정본 모두 보관 (P5 인간 개입 입증 자료). 실용신안 아님 → 저작권/상표/디자인권 각각 검토.

## 8. KPI (P4 판정 기준)

| 지표 | 의미 | 임시 기준 |
|---|---|---|
| 다음스테이지 클릭률 | 스토리가 끄는가 | Stage 클리어 후 NEXT 70%+ |
| 완주율 (S1→S3) | 첫 세션 이탈 | 50%+ |
| 재방문 D1 | 연속극 효과 | 20%+ |
| 쇼츠 평균 조회/완주 | 발견 채널 | 상대 비교(캐릭터별) |
| 노출당 제작비 | 경제성 | 시드 1개 → 파생 5개 이상 |

반응 없으면 **세계관을 갈아엎는다**(캐릭터·구조 재사용). 반응 있으면 P5.

## 9. 툴·워크플로

| 역할 | 툴 | 비고 |
|---|---|---|
| 코딩·실행 | Claude Code (이 PC, `claude --remote-control`) | 폰에서 이어보기 |
| 전략·문서·리서치 | Claude Cowork/채팅 (이 프로젝트) | 이 폴더 문서를 함께 갱신 |
| 대량 반복 코딩(선택) | Antigravity (무료) | `04_ANTIGRAVITY_HANDOFF.md` 절차로 넘김 |
| 이미지 | ChatGPT 이미지 / 기타 생성기 | 기준 이미지 참조 방식. P5 이후 ComfyUI+IPAdapter/LoRA 검토 |
| 쇼츠 | 이미지 + 자막 + TTS 조합(툴 미정) | 15~20초 |

툴이 바뀌어도 이어지는 이유: 진실은 `data/*.json` 과 `docs/` 에만 있고, 코드는 그걸 읽을 뿐이다.

## 11. 미확정 (추측으로 채우지 않는다)
- 왕자·허당남 이름. 리아 성(姓) 필요 여부.
- 쇼츠 제작 툴·나레이션 방식.
- 1차 배포 URL(자체 도메인 vs 블로그 첨부).
- 별조각 밸런스 숫자(플레이 후 조정).
